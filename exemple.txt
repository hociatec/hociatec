Guide d’intégration API — Liste & annulation des rendez-vous utilisateur
========================================================================

Contexte
--------
L’API Symfony exposée par `hociatec` propose deux routes sécurisées (JWT Bearer) permettant d’afficher les rendez-vous d’un utilisateur connecté et de changer le statut d’un rendez-vous de `confirmed` vers `cancelled`. Le flux côté client se résume à :

1. Récupérer la liste des rendez-vous de l’utilisateur courant (`GET /api/appointments/me`).
2. Afficher les sections `upcoming` (futurs) et `past` (passés), éventuellement filtrées par statut.
3. Activer un bouton « Annuler » uniquement si `isCancelable === true`.
4. Lors d’un clic sur le bouton, appeler `PATCH /api/appointments/{id}/status` avec `{ "status": "cancelled" }`, puis rafraîchir la liste.

1. Récupérer les rendez-vous
---------------------------
```
GET /api/appointments/me?status=confirmed
Authorization: Bearer <JWT>
```

- Le paramètre `status` est optionnel (`confirmed`, `cancelled`, `all`). S’il est omis ou vaut `all`, l’API renvoie tous les statuts connus.
- Réponse type :
```
{
  "status": "success",
  "data": {
    "upcoming": [
      {
        "id": 42,
        "startAt": "2025-03-07T09:00:00+00:00",
        "endAt": "2025-03-07T09:30:00+00:00",
        "status": "confirmed",
        "isCancelable": true,
        "prestation": {
          "id": 7,
          "name": "Consultation",
          "durationMinutes": 30,
          "priceCents": 4500
        }
      }
    ],
    "past": [ ... ]
  }
}
```

Implémentation front (pseudo-code) :
```ts
async function loadAppointments(token, status = 'confirmed') {
  const res = await fetch(`/api/appointments/me?status=${status}`, {
    headers: { Authorization: `Bearer ${token}` },
  });
  const payload = await res.json(); // vérifier payload.status === 'success'
  return payload.data;
}
```

2. Afficher la liste
--------------------
- `data.upcoming` contient les rendez-vous dont `startAt` est ≥ maintenant.
- `data.past` contient les rendez-vous déjà déroulés.
- Chaque rendez-vous expose `isCancelable`. Utiliser ce booléen pour décider si le CTA « Annuler » doit être affiché/activé.

3. Annuler un rendez-vous (confirmed → cancelled)
------------------------------------------------
```
PATCH /api/appointments/{appointmentId}/status
Authorization: Bearer <JWT>
Content-Type: application/json

{ "status": "cancelled" }
```

- Cette route vérifie que l’ID appartient à l’utilisateur courant et que la transition est autorisée par `AppointmentStatusManager`.
- Règles métier : on ne peut annuler qu’un rendez-vous futur (date de début strictement > maintenant) et uniquement si son statut actuel est `confirmed`.
- En cas de succès :
```
{
  "status": "success",
  "data": {
    "appointment": {
      "id": 42,
      "status": "cancelled",
      "isCancelable": false,
      ...
    }
  }
}
```
- En cas d’erreur (ex. slot passé, statut invalide) la réponse est `{"status":"error","message":"..."}` avec un HTTP 400/404 selon le cas.

Implémentation front (pseudo-code) :
```ts
async function cancelAppointment(id, token) {
  const res = await fetch(`/api/appointments/${id}/status`, {
    method: 'PATCH',
    headers: {
      Authorization: `Bearer ${token}`,
      'Content-Type': 'application/json',
    },
    body: JSON.stringify({ status: 'cancelled' }),
  });

  const payload = await res.json();
  if (payload.status !== 'success') {
    throw new Error(payload.message ?? 'Annulation impossible');
  }
  return payload.data.appointment;
}
```

4. Enchaînement UX recommandé
-----------------------------
1. Charger la liste (`loadAppointments`) lors de l’ouverture de la page « Mes rendez-vous ».
2. Pour chaque rendez-vous futur, afficher un bouton « Annuler » si `isCancelable`.
3. Lors du clic, désactiver le bouton, appeler `cancelAppointment`, puis rafraîchir la liste via `loadAppointments` pour refléter le nouveau statut.
4. Gérer les messages d’erreur retournés par l’API pour informer l’utilisateur.

Statuts supportés
-----------------
- `confirmed` (valeur par défaut lors de la création).
- `cancelled`.

Toute autre valeur provoque `Statut de rendez-vous inconnu.` (HTTP 400).
